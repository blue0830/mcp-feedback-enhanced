## Agent CLI 控制机制设计解答（未实现，仅方案）

- 文档：`docs/design/agent-cli-control.md`，需求是给 MCP 弹窗增加 CLI 监督者通道，让 A Agent 通过 CLI 向阻塞等待中的 B Agent 发反馈。
- 验证了文档所述复用点全部成立（已读源码）：
  - `WebUIManager.create_session`（main.py:329）每次 MCP 调用都创建新会话，是写注册文件的注入点
  - `WebFeedbackSession._cleanup_resources_enhanced`（feedback_session.py:766）是删注册文件的注入点
  - `submit_feedback`（feedback_session.py:519）+ `add_user_message`（576）可被 CLI 端点直接复用，零逻辑重复
  - `wait_for_feedback` 用 `run_in_executor` 跑 `feedback_completed.wait()`，事件循环不阻塞；HTTP 端点在事件循环内 `set()` 即唤醒——跨进程链路天然成立，无需额外线程/IPC
  - 现有 `/api/add-user-message` 只操作 `current_session` 不接 session_id；多实例下每进程单活跃会话，CLI 端点用 `get_current_session()` 即可，session_id 仅作路由校验
- 搜到的成熟方案：**opencode-mcp**（lobehub）几乎同构——注册文件目录 + HTTP 健康检查 prune stale + 模糊匹配 + 前缀匹配，差异仅它走 SSH 隧道跨机、本项目是 localhost 单机多实例。验证了 D1~D4 方向正确。
