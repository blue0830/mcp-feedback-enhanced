# 远程沟通指南（Discord）

`feedback-cli` 可以把每一次反馈请求同步发到你自己的 Discord 私人频道（普通文字频道或论坛频道均可），让你在手机上也能回复。允许的用户在子区（或帖子）里发出的第一条可用文字回复，效果和在本地窗口提交一样，会直接结束这次 CLI 调用。本地窗口仍会照常弹出，谁先答就听谁的。

该功能**默认关闭**，只对 `feedback-cli` 生效（MCP 服务器打开的窗口里不会出现这项设置）。

## 🧭 工作方式

- 一次 `feedback-cli` 调用对应一个子区。在文字频道里，机器人会开一个子区；在论坛频道里，机器人会发一个帖子（论坛帖子本质上也是子区）。标题是 `[项目目录名] 摘要首行 (#短ID)`；其中的首条消息包含摘要、项目目录、截止时间和回复说明，并 @ 允许的用户，手机会收到推送。
- 允许的用户在该子区里发的**第一条可用文字消息**就是最终答复，机器人会立刻回一条“已收到”。文字附件也算（Discord 会把超长文字自动转成 `message.txt`）；图片和其他文件会被忽略。
- 如果你先在本地窗口答复，子区会标记为“本地已答复”并归档。已答复、超时或被中断的子区同样会被归档。
- 回复通过每 3 秒左右的 HTTPS 轮询获取，不使用 Gateway 长连接，也没有常驻后台进程。
- 本地窗口顶部会显示远程状态（未启用 / 连接中 / 等待回复 / 不可用 / 已在远端答复 / 已在本地答复），点击即可打开远程设置。

## 🛠️ 配置步骤

### 1. 创建机器人

1. 打开 [Discord Developer Portal](https://discord.com/developers/applications)，新建一个 **New Application**。
2. 在 **Bot** 页点击 **Reset Token**，复制 Token（只会显示一次）。
3. 还是在 **Bot** 页，把 **Privileged Gateway Intents** 里的 **Message Content Intent** 打开。不开的话，Discord 返回的消息文字是空的，回复无法读取。

### 2. 准备私人服务器和私人频道

1. 使用你信任的私人服务器：摘要和回复都会保存在 Discord 上。
2. 在下面两种频道里**选一种**创建：
   - **文字频道**（任何服务器都能用）：每次请求会在里面开一个子区。
   - **论坛（Forum）频道**（服务器必须是社区服务器：服务器设置 → 启用社区）：每次请求会变成一个帖子。如果论坛要求发帖必须选标签，请至少建一个标签（机器人会使用第一个）。
3. 把频道设为**私人频道**（编辑频道 → 权限 → 私人频道），并把机器人加进去。机器人在文字频道里开的子区是公开子区，凡是能看到该频道的人都能看到内容；私人频道才能保证只有你自己能看。对机器人隐藏的频道无法使用。
4. 开启 **开发者模式**（Discord 用户设置 → 高级）。
5. 右键频道 → **复制频道 ID**；右键你自己的名字 → **复制用户 ID**。

### 3. 邀请机器人

1. 在 Developer Portal 打开 **OAuth2 → URL Generator**，勾选 scope `bot`，并授予以下权限：
   - 查看频道（View Channels）
   - 发送消息（Send Messages，在论坛里对应“创建帖子”）
   - 创建公开子区（Create Public Threads，文字频道需要；论坛不需要）
   - 在子区中发送消息（Send Messages in Threads，在论坛里对应“在帖子中发送消息”）
   - 嵌入链接（Embed Links）
   - 附加文件（Attach Files，过长的摘要会以 `summary.md` 附件发送）
   - 阅读消息历史（Read Message History）
2. 打开生成的链接，把机器人加入你的私人服务器。注意检查该频道的专属权限，确保机器人能看到它，并拥有上面这些权限。

不需要“管理子区”（Manage Threads）：机器人只归档它自己创建的子区。

### 4. 配置并测试

```bash
feedback-cli --remote-settings
```

这会打开一个只包含“远程沟通”卡片的窗口：不会产生反馈请求，除了连接测试之外也不会向 Discord 发送任何内容。请自己在前台终端里运行，它**只供人工使用，不要让 Agent 调用**。配置完成后关闭窗口即可（如果回退到了浏览器，则按 Ctrl+C，或等 `--timeout` 到期）。同样的卡片也在普通 `feedback-cli` 窗口的设置页里。

1. 填写 **Bot Token**、**频道 ID** 和 **允许回复的用户 ID**（填你自己的用户 ID；多个 ID 用逗号或空格分隔）。
2. 点击 **测试连接**（未保存的修改会先自动保存）。频道里会出现一个测试子区（或测试帖）：请在 120 秒内在里面回复任意文字。某一步如果因为网络不稳定而失败，会自动重试，最多三次，之后才报告失败。
3. 所有步骤都通过后，打开 **启用远程沟通** 开关。

修改 Token、频道或允许的用户后，验证结果会失效，功能自动关闭，需要重新测试通过后才能再次启用。Token 只写不读：保存后不会再显示，留空表示保持原来的 Token。

## 🌐 网络要求

- 只需要本机主动发起 HTTPS 出站连接：`discord.com`（接口）、`cdn.discordapp.com` 和 `media.discordapp.net`（下载文字附件）。
- 不需要公网 IP，不监听任何端口，也没有 IP 或监听地址的配置项。
- 如果本机需要代理或出口节点（例如 Tailscale 出口节点），请在系统层面配置。标准的代理环境变量（`HTTPS_PROXY`、`HTTP_PROXY`、`NO_PROXY`）会被沿用。
- 能容忍较慢或不稳定的网络：单次请求最多等 30 秒。你在 Discord 里回复后，`feedback-cli` 为了把子区标成“已答复”并归档，最多会再运行 20 秒；你在本地窗口回复时最多只等 5 秒，不会拖慢 Agent。

## ⚠️ 使用限制

- Agent 所在工具的外层超时和 `feedback-cli` 自身的超时（默认 3600 秒）仍然有效；电脑休眠或关机时也收不到回复。CLI 被强杀后子区会一直保持打开，首条消息里的“最后存活时间”会停止更新。
- 每次请求都会留下一个已归档的子区；机器人不会删除它（删除需要“管理子区”权限），想清理时请自己在 Discord 里删除。已归档的子区不占用 Discord 对活跃子区的数量上限。
- 只支持文字回复。文字附件总大小不超过 256 KiB，且必须是 UTF-8。
- 只有允许的用户的回复才算数。回复会变成 Agent 收到的指令，所以请使用私人服务器，并让允许名单尽量短。
- 远程设置只能通过回环地址（`127.0.0.1`、`localhost` 或 `[::1]`）修改，例如经 SSH 转发的 `localhost` 端口。通过其他地址打开的窗口（比如 `MCP_WEB_HOST=0.0.0.0` 后用局域网 IP 访问）无法修改。
- Token 以明文保存在 `~/.config/mcp-feedback-enhanced/remote_channel.json`（POSIX 下仅所有者可读写）。想彻底关闭，可以在卡片里关掉开关或直接删除该文件；要换存放位置，可设置环境变量 `MCP_FEEDBACK_REMOTE_CONFIG`。

## 🩺 常见问题

| 卡片上的提示 | 处理方法 |
|---|---|
| 读不到消息文字 | 打开 Message Content Intent（步骤 1） |
| 找不到该频道 | 检查频道 ID，以及机器人是否已加入服务器 |
| 该频道既不是文字频道，也不是论坛频道 | 换成文字频道或论坛（Forum）频道（不能是语音频道、分类或子区） |
| 机器人缺少权限 | 按步骤 3 给机器人在该频道授予权限 |
| Token 无效或已被撤销 | 在 Developer Portal 重置 Token 后重新填写 |
| 网络不通 | 检查代理或出口节点 |
| 该论坛要求发帖必须选标签 | 在论坛里至少创建一个标签 |
