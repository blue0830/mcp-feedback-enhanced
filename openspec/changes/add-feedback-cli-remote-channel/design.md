## Context

`feedback-cli` 采用“单调用单进程单会话”模型：`CliSessionRuntime.run()` 创建 session（每次新生成 UUID）→ 启动本地服务 → 桌面优先/浏览器回退 → `await session.wait_for_feedback(timeout)`；`shutdown()` 在 `finally` 中执行。本变更在此模型上增加一条“远程提交通道”，不改变进程模型。

与本设计直接相关的既有事实（已读代码核实）：
- `WebFeedbackSession.submit_feedback` 没有防重复：后到的提交会覆盖 `feedback_result` 与 `images`。Web 服务跑在独立线程与独立事件循环，CLI 主循环在另一个线程。
- 设置文件 `ui_settings.json` 由前端整份覆盖写（`POST /api/save-settings`），并通过 `GET /api/load-settings` 原样返回给网页；多个 CLI 窗口并存时，旧窗口的保存会冲掉新写入的键。
- 设置页原本只有在 Agent 发起请求、窗口打开时才可达（由独立入口 `--remote-settings` 解决，见决策 15）。
- `submit_feedback` 在桌面模式下通过全局 `get_web_ui_manager()` 关闭窗口；CLI 运行时的 manager 并非全局单例，该调用会新建一个默认 manager（偏好端口 8765 且自动清理占用者）。
- 桌面窗口（Tauri）只是导航到环境变量 `MCP_WEB_URL`，任意路径均可；`WebUIManager.start_server()` 不依赖会话。
- 反馈页面（`feedback.html` + `app.js`）会初始化十余个管理器并依赖会话与 WebSocket，无法直接当作无会话的设置页；设置卡片所需的样式在共享的 `styles.css` 中，`i18n.js` 可独立使用。
- MCP 窗口与 CLI 窗口使用同一套模板与路由；MCP 路径使用全局 manager，CLI 路径使用自己创建的 manager。

已对照 Discord 官方文档的外部事实：
- Gateway 的 IDENTIFY 每 24 小时最多 1000 次，超限会终止全部会话并**重置 bot token**；并发 IDENTIFY 另有每 5 秒限流。
- HTTP 接口的限制与 Gateway intents 无关；读取消息内容只取决于开发者后台的 Message Content 开关（例外：@bot 的消息、私信、bot 自己发的消息）。未开启时，消息的 `content`、`embeds`、`attachments`、`components` 都是空值。
- 附件对象包含 `filename`、`content_type?`、`size` 与带签名的 `url`；通过取消息接口拿到的链接是有效的（签名带 `ex`/`is`/`hm` 过期参数）。
- 论坛频道建帖：`POST /channels/{id}/threads` 一次完成“帖子 + 首条消息”，仅需 SEND_MESSAGES；帖子 ID 与首条消息 ID 相同。
- 消息正文 ≤ 2000 字符；embed 描述 ≤ 4096，单条消息所有 embed 合计 ≤ 6000；请求体（含文件）≤ 25 MiB。Discord 客户端对超长文字会提示转成文件附件（通常名为 `message.txt`）。
- 向未被锁定的已归档帖子发消息会自动取消归档；服务器的活跃帖子数有上限（官方未写明数值）；401/403/429 累计达到 10000 次/10 分钟会被临时封禁访问。

## Goals / Non-Goals

**Goals:**
- 远程开启后，每次 CLI 请求同步到 Discord，在帖内回复即可结束本地等待。
- 一次调用对应一个帖子，回复不串线。
- 不引入常驻后台、不使用 Gateway、不新增第三方依赖。
- 远程故障不影响本地；只有白名单用户的回复才生效；配置与 token 独立且安全存放。
- 渠道接口保持最小，便于日后接入其他渠道。
- 提供不占用 Agent 请求的独立设置入口；MCP 窗口不出现该功能。
- 长文字回复（文字附件）可用。

**Non-Goals:**
- 图片与非文字附件回复、按钮交互、合并多条消息的等待窗口。
- Agent 级会话聚合（多次调用共用一个帖子）。
- Discord 以外渠道的实现；常驻中转服务。
- 远程开启时不弹本地窗口的模式。
- 独立设置页里的非远程类设置（语言、布局等）。

## Decisions

1. **绑定粒度：一次调用 = 一个帖子**
   - 决策：帖子与 session 一一绑定，对应关系只存在于进程内存；帖子标题和首条消息带短 session ID 便于人工对应。
   - 原因：CLI 拿不到 Agent 的会话 ID；不需要持久映射；同一帖子不会同时承载多个未答请求。
   - 备选：Agent 级聚合。放弃原因：需要稳定 key（依赖模型传参或用目录，后者会串）、持久映射、归档复活，并发提问时无法区分回复属于谁。
   - 升级路径：后续可选 `--thread-key`——同 key 且无未答请求时复用帖子，回复以“晚于本次提示消息”为界（已确认后置，不在本次范围）。

2. **渠道接口：三步**
   - 决策：`RemoteChannel` 仅含 `open(request)`、`wait_reply(handle)`（可取消）、`close(handle, outcome)`。存活标记等渠道内部行为放在 `wait_reply` 实现内。`RemoteSessionCoordinator` 负责后台运行、异常隔离、状态上报、提交与收尾。
   - 原因：保持最小；Telegram 的取消息只允许单消费者（多进程并发会冲突），接入时需常驻中转，现在不提前设计。
   - 备选：一开始抽象出完整的事件/订阅模型。放弃原因：过度设计。

3. **监听方式：每个 CLI 进程自己定时查询，不做常驻**
   - 决策：`GET /channels/{thread_id}/messages?after=<cursor>&limit=100`，间隔约 3 秒（带抖动）；游标初始为首条提示消息 ID，只处理更大的 ID。HTTP 客户端用已有的 `aiohttp`，开启 `trust_env` 读取代理环境变量；连接超时 5 秒、总超时 10 秒。
   - 错误分类：Discord API 请求 401/403 → 永久失败并停止轮询（避免触发无效请求封禁）；429 → 按 `Retry-After` 等待；5xx/网络错误 → 指数退避（上限 30 秒）并上报“远程不可用”，恢复后回到等待状态。附件下载不属于 API 请求，其失败不适用上述分类（见决策 4）。
   - 网络要求：只需要本机**主动出站**访问 `discord.com`（接口）与 `cdn.discordapp.com` / `media.discordapp.net`（下载文字附件）；不需要公网 IP、不开放任何入站端口，也没有“监听地址”之类的配置项。本机需要代理或出口节点（系统代理、环境变量代理、Tailscale 出口节点等）时沿用系统层设置。
   - 原因：Gateway 每次启动都算一次登录，并发 CLI 会撞上 24 小时 1000 次上限（触发 token 重置）和 5 秒并发限流；轮询各进程互不影响。
   - 备选：常驻中转进程 + Gateway。放弃原因：与“无 daemon”约束冲突，且对当前诉求过重；代价是约 3 秒延迟、不支持按钮。

4. **回复识别：白名单用户的第一条有效文字消息（含文字附件）**
   - 决策：作者 ID 在白名单内、非 bot、普通消息/回复类型，且“可用文字”非空 → 视为最终答复；立即回复“已收到”，再提交。其他消息一律忽略。
   - 可用文字 = 消息正文（去空白）+ 各文字附件的内容，按顺序以空行拼接。
   - 文字附件：`content_type` 以 `text/` 开头，或文件名以 `.txt` / `.md` 结尾；主要用于承接 Discord 对超长文字自动生成的 `message.txt`。
   - 读取规则：只读消息对象里的附件 `url`；必须是 https 且主机为 `cdn.discordapp.com` 或 `media.discordapp.net`，不跟随跳转到其他主机；下载请求不带 bot token；附件总大小上限 256 KiB（先看声明的 `size`，再按实际读取字节数截断判断）；内容必须是合法 UTF-8（允许 BOM）且不含 NUL 字节。下载沿用 5 秒连接 / 10 秒总超时。
   - 读取失败（过大 / 非 UTF-8 / 二进制 / 主机不符 / 下载失败或超时）视为“不可用消息”：机器人提示原因并继续等待，游标照常前进，由用户重发；不自动重试。下载的 401/403（例如链接过期）只算这条消息不可用，**不得**按决策 3 判为凭据失败。
   - 图片与其他非文字附件一律忽略。没有可用文字 → 提示“仅支持文字（消息正文或文字附件）”并继续等待；有可用文字但还带被忽略的附件 → 文字生效，回执注明“部分附件已忽略”。
   - 原因：与本地“提交一次”一致，无额外等待；只认白名单避免任何能进频道的人指挥 Agent；长回复在手机上最常见的形态就是 `message.txt`，不读取会让第一版在长回复时体验断裂。
   - 备选：合并窗口 / 结束标记 / 反应确认。放弃原因：增加延迟或操作成本。

5. **提交路径：复用同一入口并接入先到先得裁决**
   - 决策：远程回复以来源 `remote:discord` 走与本地相同的提交入口，经 `harden-agent-cli-feedback-control` 的原子抢占（任务 1.1–1.4）；在 Web 服务线程的事件循环中执行（`run_coroutine_threadsafe`），保证给窗口的“已提交”通知可正常发送。成功后记录 `submission_method="discord"` 的用户消息。抢占失败 → 协调器按“本地已答”收尾。
   - 原因：避免并发覆盖；避免跨事件循环使用 WebSocket。
   - 前置：该裁决必须先落地，本变更不重复实现。

6. **收尾：有界、尽力而为**
   - 决策：`CliSessionRuntime` 记录结束原因，`shutdown()` 传给协调器；协调器在总计数秒内完成：编辑首条消息为最终状态（远程已答 / 本地已答 / 超时 / 中断 / 错误）、必要时补一条说明、归档帖子（`PATCH archived=true`）。建帖时设 `auto_archive_duration=1440` 作为兜底，避免与默认超时（3600 秒）同一时刻自动归档。
   - 原因：避免占满服务器活跃帖子上限；让人一眼知道结果。
   - 限制：进程被强杀时无法收尾，见下一条。

7. **存活标记**
   - 决策：首条消息写明截止时间（创建时间 + timeout）；轮询循环内每 60 秒编辑首条消息的“最后存活时间”，编辑失败静默忽略。
   - 原因：强杀后帖子会看似仍在等待，回复无人处理；时间戳停止更新即可一眼识别。

8. **配置独立存储**
   - 决策：`~/.config/mcp-feedback-enhanced/remote_channel.json`，临时文件 + replace 原子写，POSIX 下尽力设 0600。字段：`enabled`、`provider`、`verified_fingerprint`、`discord{token, forum_channel_id, allowed_user_ids}`。独立接口：读取脱敏（只返回 `token_set`）；保存时 token 缺省=保持原值；日志不得出现 token。每次 CLI 调用启动时读取最新配置，不缓存；调用期间配置再被修改（含关闭开关）不影响已在等待的调用，变更从下一次调用开始生效。不经前端通用设置对象回写。
   - 备选：放入 `ui_settings.json`（放弃：整份覆盖 + 原样回传）；环境变量（放弃：界面无法管理）；系统凭据库（放弃：新增依赖与跨平台差异，可作为后续升级）。

9. **启用前置：验证指纹**
   - 决策：仅当 `verified_fingerprint` 等于当前配置指纹时，`enabled` 才生效；指纹为 (provider, token, channel_id, 排序后的 allowed_user_ids) 的 SHA-256 摘要（不存明文）。修改任一项自动视为未验证、未启用。
   - 原因：杜绝“已启用但从未验证”的状态。

10. **测试流程（设置页“测试”按钮）**
    - 决策：依次验证并逐项返回结果：token 有效（`GET /users/@me`）→ 频道存在且为论坛类型（`GET /channels/{id}`）→ 实际建一个测试帖（验证发帖与发言权限）→ 要求白名单用户在帖内回复一句，读取并确认文字非空（验证 Message Content 与用户 ID）。最长等待 120 秒；全部通过才写入验证指纹；测试帖随后归档。
    - 接口形态（实现时补充）：测试要等人回复，最长约 2 分钟，因此是异步的。`POST /api/remote-config/test` 立即返回 202 与 `run_id`，页面再轮询 `GET /api/remote-config/test/{run_id}` 读取逐步结果（`token` / `channel` / `post` / `reply` / `archive`，以及是否已写入验证、`reply_timeout_seconds`）。同一窗口同时只跑一次：重复点击得到 409 并带回正在运行的 `run_id`，页面改为跟随它，不会建出两个测试帖。
    - 收尾与边界（实现时补充）：`archive` 是可选步骤，归档失败只让测试帖保持打开，不影响“通过”；任一步失败、被取消或窗口关闭时，会尽力归档测试帖。验证指纹只在“全部必需步骤通过，且测试期间设置没有被改动”时才写入，否则报 `config_changed`，不落盘。
    - 原因：“配置成功”必须是全链路实测，而不是字段非空。

11. **失败隔离与状态上报**
    - 决策：协调器是后台任务，启动时不等网络，不阻塞窗口与 `wait_for_feedback`；所有异常在协调器内捕获；状态（关闭 / 连接中 / 等待回复 / 不可用(原因) / 远程已答 / 本地已答）经 WebSocket 推送给本地窗口显示。未启用或配置无效时不创建任何远程对象。

12. **转发格式**
    - 决策：帖子标题 `[项目目录名] 摘要首行 (#短ID)`，截断到 100 字符；首条消息用 embed：描述放摘要（≤4000 字符，超出则截断并把完整摘要作为 `summary.md` 附件）、字段含项目目录 / 短 session ID / 截止时间 / 回复说明；消息 @ 白名单用户以触发推送，`allowed_mentions` 仅放行白名单用户，防止摘要内的 @everyone 等被解析。

13. **顺带修复：关闭桌面窗口不再经全局管理器**
    - 决策：会话持有所属 manager 的引用（或关闭回调），`submit_feedback` 用它关闭窗口，不再调用 `get_web_ui_manager()`。MCP 路径行为不变（其 manager 即全局单例）。
    - 原因：远程提交与本地提交共用该路径，避免新建默认 manager 触发端口自动清理。

14. **作用范围：仅 CLI；MCP 窗口不显示卡片**
    - 决策：仅 `CliSessionRuntime` 启动协调器；MCP 入口不接入。`WebUIManager` 增加“远程设置可用”标志（默认 False，由 CLI 运行时置 True，请求时读取）；模板据此决定是否渲染设置卡片，远程配置接口在标志为 False 时返回 404，卡片脚本在找不到卡片元素时不初始化。
    - 原因：MCP 窗口里开关可见但无效，会误导用户以为远程已生效。

15. **独立设置入口：`feedback-cli --remote-settings`**
    - 决策：新增 `--remote-settings`，与 `--summary` / `--summary-file` 互斥，`--timeout` 作为最长存活时间。由一个独立的小型运行时承载：创建 manager 并置 CLI 托管标志 → `start_server()`（不创建会话）→ 桌面优先、失败回退浏览器（复用同一段启动逻辑）→ 打开 `/remote-settings` → 等待结束。
    - 页面：新增最小模板 `remote_settings.html`，只加载共享样式、`i18n.js` 与卡片脚本，不依赖会话与 WebSocket；卡片是与设置页共用的同一个组件（模板 include + 同一份脚本）。语言只读取 `ui_settings.json` 的 `language`，不写回任何通用设置。
    - 结束：桌面模式下桌面窗口进程退出即结束；浏览器回退模式无法感知页签关闭，靠 Ctrl+C 或 `--timeout` 结束；Ctrl+C 与超时都视为正常退出（退出码 0）。
    - 不做的事：不创建会话、不启动远程协调器、不参与先到先得裁决、不向 Discord 转发任何内容（测试按钮除外）。
    - 原因：反馈页面整体依赖会话与 WebSocket，强行复用需要改动大量既有逻辑；单独的小页面 + 共用卡片改动最小。用户手工跑一次普通 `feedback-cli` 也能打开设置页，但在远程已启用时这个占位请求会被转发到 Discord，独立入口可避免。
    - 备选：终端向导（放弃：与“设置界面 + 开关”的预期不一致，校验提示要另写一套）；造占位会话打开完整反馈窗口（放弃：会被当成真实请求）。
    - 限制：仅供人工在终端使用（沿用前台、需要 TTY 的限制）；Agent 误调会阻塞到窗口关闭或超时，文档注明。

16. **配置接口的本机同源保护**
    - 决策：远程配置的读取、保存、测试接口统一经过一个校验：`Host` 头的主机名必须是 `127.0.0.1` / `localhost` / `[::1]`（挡 DNS 重绑定）；写请求必须是 `Content-Type: application/json`（跨站“简单请求”无法伪造该类型且跨域预检会失败）；带 `Origin` 头时必须与 `Host` 同源。不通过返回 403，不修改任何配置。
    - 原因：这些接口能改写 token、白名单与启用开关，而白名单用户的回复直接成为 Agent 指令；本地随机端口并不能防止网页跨站请求或 DNS 重绑定。
    - 限制：通过非回环地址（如 `MCP_WEB_HOST=0.0.0.0` 后经局域网 IP）访问的窗口无法配置远程通信；通过 SSH 端口转发到 `localhost` 访问不受影响。

## Risks / Trade-offs

- [进程被强杀，帖子遗留] → 截止时间 + 存活标记；窗口/CLI 正常退出路径尽力收尾。
- [约 3 秒延迟、无按钮] → 可接受；需要时另立变更引入常驻中转。
- [token 明文存于用户目录] → 独立文件、最小权限、只写不读、日志脱敏；后续可换系统凭据库。
- [摘要外发第三方] → 默认关闭；设置页明确提示；只发到用户自己的私有服务器。
- [回复即指令] → 白名单必填；无白名单则不可启用。
- [限流 / 封禁] → 读取响应头、401/403 立即停止、轮询间隔设下限。
- [活跃帖子上限] → 结束即归档。
- [网络不可达（需要代理的环境）] → 读取代理环境变量，短超时，失败隔离。
- [本地与远程同时回复] → 先到先得裁决，失败方收尾为“本地已答”。
- [外层限制不变] → CLI 仍受 Agent 所在工具超时与电脑休眠/关机约束；在文档中明确“远程不等于可以离线回复”。
- [附件读取引入额外外部请求] → 主机白名单、不带凭据、不跟随跳转、256 KiB 上限、严格 UTF-8；任何失败只让该条消息不可用，不影响会话。
- [Agent 误调 `--remote-settings`] → 会阻塞到窗口关闭或超时；文档注明仅供人工使用。
- [非回环访问无法配置远程通信] → 文档说明改用 SSH 端口转发。
