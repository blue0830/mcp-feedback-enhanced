## Context

当前目标是在不移除原有 MCP 入口前提下，为 Agent 增加 `feedback-cli` 阻塞入口。已确认的一版边界是“运行时二选一（MCP 或 CLI）”，但代码层仍需兼容保留两套入口。现有风险集中在多实例并发下的端口分配、窗口路由、子进程生命周期和临时资源清理。

约束如下：
- 反馈行为语义尽量与现有 MCP 保持一致（默认参数、超时提示、错误提示、返回文本风格）。
- CLI 专供 Agent 调用，不以人工终端交互为主目标。
- 多实例通过进程隔离实现，不引入 daemon、全局注册表、跨进程 `list/reply`。

## Goals / Non-Goals

**Goals:**
- 增加 `feedback-cli` 命令，支持一次调用一次会话的阻塞等待。
- 保证多实例并发隔离：每次 CLI 独立 Session、独立后端、独立端口、独立窗口。
- 保持“桌面优先，失败回退浏览器”，且窗口手动关闭不触发取消。
- 统一结果回传与资源清理：文本语义兼容 MCP，图片路径可读且可回收。
- 修复已识别的关键实现风险（端口竞态、固定端口、日志字段、PIPE 堵塞、强杀残留）。

**Non-Goals:**
- 不设计跨进程会话发现与远程控制能力。
- 第一版不新增 `--json` 输出协议。
- 不引入长期驻留服务（daemon）或复杂实例调度器。

## Decisions

1. **入口分离、核心复用**
   - 决策：新增 `feedback-cli` 入口，复用现有 Web 会话和反馈核心逻辑，保留原 MCP 入口。
   - 原因：最小改动达成兼容，避免重写导致语义分叉。
   - 备选：重写独立 CLI 核心。放弃原因：工作量大且易与 MCP 产生行为漂移。

2. **多实例模型采用进程隔离**
   - 决策：每次 CLI 调用创建独立 `WebUIManager` 和 Session，不共享会话状态。
   - 原因：天然隔离结果回传，避免跨调用污染。
   - 备选：全局注册表 + 进程内复用。放弃原因：引入路由一致性和并发复杂度。

3. **端口策略改为系统分配**
   - 决策：CLI 路径绑定端口 `0`，由操作系统分配临时端口，再将实际 URL 注入前端。
   - 原因：消除“先探测后绑定”竞态。
   - 备选：固定端口池扫描。放弃原因：并发冲突概率高。

4. **前端不允许固定回退到 8765**
   - 决策：桌面前端重试、跳转、健康检查全部基于注入的 runtime URL。
   - 原因：固定端口会破坏多实例路由。
   - 备选：仅后端修端口。放弃原因：前端仍可能跳错端口。

5. **桌面失败回退浏览器，但手动关窗不取消**
   - 决策：仅在桌面启动失败/崩溃时自动回退浏览器；用户手动关闭后不重开窗口，CLI继续等待反馈或超时。
   - 原因：匹配已确认产品行为，避免误判取消。
   - 备选：关窗即取消。放弃原因：与多实例场景冲突。

6. **图片返回路径 + TTL 清理**
   - 决策：图片按 Session 写入独立临时目录并返回路径；默认 TTL 1 小时，启动/退出时清理过期文件。
   - 原因：兼顾可读性与输出体积，不返回大段 Base64。
   - 备选：退出即删。放弃原因：Agent 拿到失效路径。

7. **子进程输出处理**
   - 决策：Tauri 子进程标准输出/错误不走无人消费 PIPE（默认 DEVNULL，调试时写文件或受 `MCP_DEBUG` 控制）。
   - 原因：避免缓冲区写满导致卡死。
   - 备选：保留 PIPE。放弃原因：高概率运行卡顿。

8. **中断与清理策略**
   - 决策：正常退出/超时/中断路径统一执行有界清理；强制终止场景通过进程组（Windows Job Object）回收子进程。
   - 原因：降低孤儿窗口和残留端口概率。
   - 备选：仅依赖 finally。放弃原因：强杀时不可靠。

## Risks / Trade-offs

- [Risk] 外层工具超时小于 CLI timeout，CLI 被提前杀死 → Mitigation：在调用文档中强制声明外层超时需大于 CLI timeout，并补充示例。
- [Risk] 与 MCP“语义一致”理解偏差导致行为分叉 → Mitigation：显式定义一致范围为“用户可见文本语义/默认参数/错误分类”，非实现细节完全一致。
- [Risk] 多实例窗口人工识别困难导致误提交 → Mitigation：在页面展示项目路径、摘要和短 Session 标识。
- [Risk] TTL 清理过短导致路径失效，过长导致堆积 → Mitigation：默认 1 小时并支持清理命令，后续依据使用数据调整。
